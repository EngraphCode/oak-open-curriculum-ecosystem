7 · What the baseline says, in four sentences

1. The declared four-level hierarchy and the real structure diverge — the runtime spine is one small confirmed core sink plus domain clusters, with the declared libs/sdks seam bidirectional in production.

2. The real law is islands of hard enforcement in a sea of convention — six depcruise rules, a design fence, a membership whitelist — while whole change-clock families have no mechanical signature.

3. Lifecycle mixing is universal where generation exists: no generated-only package, four clocks inside one workspace at the worst site, 42.5% of tracked bytes generated-or-data.

4. The toolkit ambition is currently inverted: reusable machinery sits inside Oak leaves (OAuth-for-MCP, the OpenAPI pipeline, index lifecycle machinery), three built libraries have zero consumers, and nothing ships as a building block.

8 · Change proposals

Each proposal lands below as a designed change with its own diagram, per the brief's five points: the existing architecture holds no privilege; the thinnest possible Oak on reusable code; foundations designed to library grade and effectively finishable — constitutive of the conceptual shape, not a cleanup phase; one lifecycle per package; a toolkit that can build any digital service. Queued for design on the evidence above:

Change 1 · The foundation layer, designed

Establish a chartered foundation tier: a small set of packages, each the canonical form of one standard concept, designed to be finished. This tier is the constitutional part of the toolkit — brief points 3 and 5 made structural — and its design is part of the repo's conceptual shape, not a cleanup phase. The estate's embedded instances serve as demand evidence and test cases; each package is designed from the concept's canonical form, never extracted from incumbent code (point 1 applied at code scale).

The charter. Admission requires a standard concept whose contract can be stated without Oak, any vendor, or any consumer class; at least one embedded estate instance as demand evidence (standard concepts do not wait for a second consumer); and a closed public API statable without present callers. The finish bar, declared at each package's birth: exhaustive tests (property-based where the concept warrants them), full documentation, a performance characterisation, and tier-closed dependencies — foundation depends only on foundation, preserving the one structural property the current core already proves. A finished package is done: its clock is designed flat, and later change is exceptional and deliberate. Finished is an observable, not a mood: ratified contract + green exhaustive suite + perf record + flat clock over a declared window + live consumers (§6 makes the clocks measurable; a flat clock alone can be abandonment).

The v1 concept set, with its demand evidence. Today's core is a mixed bag: genuine concept packages sit beside build infrastructure on a different clock, and two of the ten name a consumer class in their own descriptions — "for MCP applications" inside a tier that must not know its consumers.

Warrant. Brief points 3 and 5 name this layer; the baseline shows its embryo already confirmed (§2's closed core sink) and shows the defects the charter ends: consumer-scoped naming inside core, the env duplication, vendor glue beside contracts, and build infrastructure sharing a tier with runtime foundations. Evidence basis: the manifest and dependents sweeps plus the measured clocks above — no whole-estate enumeration was needed, so the design-first order holds for this change.

Falsifiers. A concept whose contract cannot be stated without Oak, vendor, or consumer specifics is relocated, not admitted. A concept with no embedded estate instance is deferred — demand unevidenced. If a finished package's clock will not go flat because consumers keep forcing contract change, the concept was mis-drawn: split or re-draw it rather than reopening the contract piecemeal.

Spend. This change is design; the per-package finish work (contract, tests, docs, perf) is priced per package at its own card before any of it starts.
