## Executable surface (all nine scripts read)

Payload: `scripts/` under the installed skill — `__init__.py` (empty),
`utils.py`, `quick_validate.py`, `package_skill.py`,
`aggregate_benchmark.py`, `generate_report.py`,
`improve_description.py`, `run_eval.py`, `run_loop.py`.

- **Lifecycle**: NOTHING auto-runs. No hooks, no install-time code, no
  session-start injectors; no host surface (package.json scripts, CI
  workflows, `.agent/hooks`) invokes any payload script — verified by
  tree grep. Every script runs only on explicit human/agent invocation
  per the skill's documentation.
- **Process spawn**: `improve_description.py` and `run_eval.py` spawn
  the LOCAL `claude` CLI (`claude -p --output-format text`, prompt on
  stdin). They deliberately unset the `CLAUDECODE` env var to permit
  nesting `claude -p` inside a session — flagged as the payload's most
  sensitive behaviour together with the next item. `run_loop.py`
  orchestrates these; no other subprocess use exists.
- **Harness-visible mutation**: `run_eval.py` writes a command file
  into the project root's `.claude/commands/` so the skill under test
  appears in the spawned session's skill list. Transparent,
  eval-scoped, but it is a write into harness configuration — future
  invokers should know it happens.
- **Network reach**: none direct — no sockets/requests/urllib in the
  payload. Indirect reach only via (a) the spawned `claude` CLI under
  the user's own Anthropic auth (the same trust boundary as any
  interactive use) and (b) Google Fonts `<link>` tags in HTML reports
  generated by `generate_report.py`, fetched at browser-view time, not
  at script runtime.
- **Filesystem**: eval workspaces, benchmark JSON/MD, `.skill` zip
  output (`package_skill.py` via `zipfile`), a temp live-report file
  (`run_loop.py`, which also calls `webbrowser.open` on the LOCAL
  file). No writes outside the working tree / temp.
- **Exfiltration / injection vectors**: prompt content flows to the
  Anthropic API via the user's CLI — no third-party endpoints; no
  eval/exec of remote content; report generation HTML-escapes via the
  `html` module.
- **Supply chain**: `quick_validate.py` imports third-party `yaml`
  (PyYAML) undeclared — fails CLOSED (`ModuleNotFoundError`) on a
  clean interpreter; no runtime pip installs.

## Verdict

**Safe at rest; safe on explicit invocation within the user's own
`claude` auth boundary**, at the content pinned by the lock hash. Two
hygiene flags for invokers (the `.claude/commands/` write and the
`CLAUDECODE` unset) and two known upstream defects (packager must run
from the skill root or `ModuleNotFoundError: scripts`; undeclared
PyYAML) — dispositioned on #714 as upstream-routed, since local
patches to installer-managed content would break the lock's content
hash and the owner's two-channel ruling forbids grandfathering local
forks. Re-review fires at the next pin bump per the rule.
