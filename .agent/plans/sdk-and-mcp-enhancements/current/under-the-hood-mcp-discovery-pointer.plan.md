# Under-the-Hood MCP discovery pointer (sticking-plaster precursor)

**Status**: 🟡 current — queued, and part of the upcoming team session. **Sticking-plaster**:
the proper fix is the architectural deep dive in
[`mcp-tool-taxonomy-and-orientation.plan.md`](mcp-tool-taxonomy-and-orientation.plan.md).

## Problem and intent

An agent connecting to the Oak MCP server does not discover the orientation capability
(`oak-under-the-hood`). Confirmed first-hand (2026-06-28): the MCP **discovery surface** — the
server-instructions string in the initialize response, generated by `generateServerInstructions()`
(`packages/sdks/oak-curriculum-sdk/src/mcp/agent-support-tool-metadata.ts`) — names only
`get-curriculum-model`. So an agent's first-session prior never mentions orientation, and a
"how is this built / what is this / how does the MCP work" query is served (at best) by the
curriculum tools or not at all.

**Root cause (owner, 2026-06-28): the curriculum↔orientation separation was taken too far.** The
orientation tool was held so far from the curriculum machinery that it fell off the discovery
surface entirely. The cure is not more isolation — it is to relax the separation at the discovery
surface with one pointer sentence.

## The fix (one sentence on the discovery surface)

Add a pointer sentence to the server-instructions discovery surface, of the shape:

> For questions that are not about curriculum content — about the mechanisms by which the content
> is delivered, about this MCP app or its associated services, or about the repository itself —
> use the `oak-under-the-hood` tool to orient yourself to the Oak Open Curriculum Ecosystem.

Simplest form: a static sentence in the `generateServerInstructions()` template (not via the
metadata loop — it needs no `callAtStart` / `seeAlso` / context-hint entanglement; it is a plain
pointer). The exact wording is refined at implementation.

## Mechanism

Every connected agent reads the server instructions at conversation start, so naming orientation
there is the highest-leverage discovery fix for the smallest change. It deliberately relaxes the
over-separation: the discovery surface may name the (currently app-local) orientation tool — that
crossing is the point, not a violation.

## Acceptance

- The generated server instructions name `oak-under-the-hood` and route non-curriculum / mechanism
  / MCP-app / repo questions to it (behaviour test on the generated string).
- Value-proxy (run it, observe): against a real client / MCPJam, an orientation or "how is this
  built" query reaches `oak-under-the-hood`, and a curriculum query still routes to the curriculum
  tools (the content separation holds; only the discovery surface is bridged).

## Non-goals (YAGNI)

- The architectural fix — unifying the tool taxonomy, SSOT-deriving the tool-listing surfaces,
  deciding orientation's registry home, per-tool response decoration. That is
  [`mcp-tool-taxonomy-and-orientation.plan.md`](mcp-tool-taxonomy-and-orientation.plan.md)
  (owner-gated WS0 deep review). This plan does not pre-empt it.
- Entangling orientation into `AGENT_SUPPORT_TOOL_METADATA` / the curriculum context-hint and
  `seeAlso` machinery — wrong shape; the pointer is a plain sentence.
- Description trigger-phrase tuning, resource-annotation work, cross-references — out of scope for
  the sticking-plaster; the architectural fix subsumes them.

## Relationship and lifecycle

Precursor to (and feeds) `mcp-tool-taxonomy-and-orientation.plan.md`: it delivers immediate
discoverability and confirms the gap live; the architectural review then **replaces** this sentence
with the proper unified surfacing (the sentence is an owner-sanctioned precursor, removed when the
proper fix lands — not a permanent bridge). Part of the upcoming team session
(`../../agent-tooling/current/team-tooling-session-2026-06-28.plan.md`).

## Foundation alignment

principles.md §Simplicity (could-it-be-simpler — one sentence); value-first (the separation is
malleable — relax it); the cowpath anti-pattern (do not preserve the over-separation as a
constraint to design around). TDD per testing-strategy.md (behaviour test on the generated
discovery string, never a content pin).
